**Title**

fix: private key authentication never sets AuthToken.Expiry, so the OAuth2 token is never renewed

---

**Current zscaler-sdk-go version**

v3.8.48

---

**Description**

`Authenticate` parses `expires_in` and sets `token.Expiry` (`zscaler/oneapiclient.go`), but
`authenticateWithCert` - the private key / client assertion path - unmarshals the response and returns it
without touching `Expiry`:

```go
var tokenResponse AuthToken
err = json.Unmarshal(body, &tokenResponse)
if err != nil {
    return nil, fmt.Errorf("error parsing response: %v", err)
}

return &tokenResponse, nil
```

`AuthToken.Expiry` therefore stays at its zero value for every private-key client. In
`startTokenRenewalTicker`, `renewalInterval := time.Until(tokenExpiry) - time.Minute` is then hugely negative,
the `if renewalInterval > 0` guard fails, and no ticker is ever started.

**Impact:** a client authenticated with a private key never renews its access token. Once the token expires
(one hour), every subsequent API call fails until the process is restarted. Client-secret clients are
unaffected because they go through `Authenticate`, which sets the expiry.

**Suggested fix:** set the expiry in both paths, ideally by extracting the shared parsing so the two cannot
drift again.

---

**Reproduction**

Authenticate with `WithClientID` + `WithPrivateKey` + `WithVanityDomain`, then inspect
`cfg.Zscaler.Client.AuthToken.Expiry`: it is the zero time, while the same code with `WithClientSecret`
returns an expiry one hour out. With debug logging on, the `parsed expires_in=... token expiry set to: ...`
line appears only for the client-secret path.
